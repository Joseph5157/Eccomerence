# medistore

A full-stack demo e-commerce store for vitamins, syrups and supplements.

- **`/frontend`** — Next.js 15 (App Router, TypeScript, Tailwind CSS), storefront UI + cart + checkout.
- **`/backend`** — Medusa v2 commerce engine (Store/Admin APIs, products, orders).

## Prerequisites

- Node.js 20+
- Docker Desktop (for the local Postgres + Redis used by the backend)

## Running locally

### 1. Start the backend's database

```bash
cd backend
docker compose up -d       # starts Postgres on :5442 and Redis on :6379
cp .env.example .env       # already pre-filled for the docker-compose services
npm install
npm run db:migrate         # or: npx medusa db:migrate
npm run seed                # seeds the 9 medistore products + an India/INR region
```

The seed script prints a **publishable API key** at the end — copy it.

### 2. Start the backend

```bash
npm run dev                 # Medusa admin + Store API at http://localhost:9000
```

The Medusa admin dashboard is at `http://localhost:9000/app` (you'll be prompted to create the first admin user on initial load — use `npx medusa user -e you@example.com -p yourpassword` if you'd rather create one from the CLI).

### 3. Start the frontend

```bash
cd ../frontend
cp .env.example .env.local
# paste the publishable key from step 1 into NEXT_PUBLIC_MEDUSA_PUBLISHABLE_KEY
npm install
npm run dev                 # storefront at http://localhost:3000
```

If the backend isn't running or the publishable key isn't set, the frontend automatically falls back to a hardcoded copy of the product catalog so every page still renders — you just won't be hitting live Medusa data (cart/checkout still work fully client-side either way).

### Run both at once

Open two terminals — one running `npm run dev` in `/backend`, one running `npm run dev` in `/frontend` — or use a process manager like `concurrently`/`turbo` from the repo root if you prefer a single command.

## Payments

Checkout has a **"Pay with Razorpay"** button that is currently stubbed (`frontend/src/lib/payments.ts`) — it simulates a successful payment and clears the cart. To wire up real Razorpay:

1. Add `RAZORPAY_KEY_ID` / `RAZORPAY_KEY_SECRET` to `backend/.env` and register Razorpay as a Medusa payment provider in `medusa-config.ts`.
2. Add `NEXT_PUBLIC_RAZORPAY_KEY_ID` to `frontend/.env.local`.
3. Replace `payWithRazorpayStub` with a real call to Razorpay's Orders API (server-side) + `checkout.js` (client-side), verifying the payment signature before marking the order paid.

## Deploying to Railway (later)

Both services deploy independently as two Railway services in the same project:

1. **Create a Railway project** and add a **Postgres** and **Redis** plugin (or use Railway's managed databases).
2. **Backend service** — point it at `/backend`, set:
   - `DATABASE_URL`, `REDIS_URL` → Railway's provided connection strings
   - `STORE_CORS`, `ADMIN_CORS`, `AUTH_CORS` → your deployed frontend's URL
   - `JWT_SECRET`, `COOKIE_SECRET` → random secrets
   - `RAZORPAY_KEY_ID` / `RAZORPAY_KEY_SECRET` / `RAZORPAY_WEBHOOK_SECRET` once live
   - Build command: `npm run build`; start command: `npm run start`
   - Run `npm run db:migrate` and `npm run seed` once via a Railway shell/job after first deploy
3. **Frontend service** — point it at `/frontend`, set:
   - `NEXT_PUBLIC_MEDUSA_BACKEND_URL` → the backend service's public Railway URL
   - `NEXT_PUBLIC_MEDUSA_PUBLISHABLE_KEY` → the key generated by the seed script
   - `NEXT_PUBLIC_RAZORPAY_KEY_ID` once live
   - Build command: `npm run build`; start command: `npm run start`
4. Generate public domains for both services and update `STORE_CORS`/`AUTH_CORS` on the backend to match the frontend's final domain.
